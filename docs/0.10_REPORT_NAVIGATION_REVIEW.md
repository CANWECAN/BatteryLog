## Correction and behavior

Large violation tables retain every event record in an inert JSON element,
including the previously displayed evidence and original interval endpoints.
Only 100 rows at a time become live table elements. Small tables of at most
100 events remain static. A small inline script supplies first/previous/next/
last navigation and filters by rule, exact signal and overlapping time interval.
Rule-count links select that rule's events.

The existing numeric display precision is preserved. Time filtering uses
original event bounds; it does not apply the engineering boundary guard or
round source timestamps. Filters affect only the table: charts, result JSON,
overall status and global counts retain the complete analysis. An empty match
must never imply PASS. Sticky headers and a keyboard-focusable scroll region
keep evidence context available while reading a page.

The report remains self-contained and has no new runtime dependency or
JavaScript framework. The canonical JSON result is unchanged. This is a
presentation change, not event truncation or an analysis-policy change.

Two material behavior limits are explicit in the UI and technical reference:

- JavaScript is needed to browse/filter all large-table pages. When disabled,
  the first 100 events and a notice are shown; all records remain embedded.
- Printing includes the currently displayed page, not every event. Use canonical
  JSON for complete machine-readable evidence.

## Own diagnostic corrections

The initial baseline had no automatic memory sampler guard; observed pressure
was handled by stopping only the owned browser. Final runs sample owned Edge
working sets every 200 ms and stop at a 4 GiB sum or below 1 GiB global available
RAM. These diagnostic stop conditions are not published product capacity limits.

An early header test checked the thead box rather than its sticky th cell;
the corrected browser probe checks the visible cell. A first pack-chain test
assumed a golden contained a mismatch event; the final test produces that event
from known 8 V pack / 7 V cell-sum input and checks the exact displayed chain.
Ruff also caught late-bound diagnostic closures, which were bound explicitly.
An overlapping build/browser diagnostic was discarded; final measurements
were rerun without build or test workloads.

## Remaining limits and reproduction

The output still contains complete SVG evidence and all serialized event
records. Pagination limits live table rows, not the file size, parsing cost,
SVG node count or total memory. The measured report still has about 301,629 DOM
nodes. There is no fixed-memory guarantee or maximum supported log size.
Large data-quality-event tables are not covered by this change. Only synthetic,
aligned four-cell/two-temperature input and one Edge version were measured;
other browsers and representative vendor recordings remain acceptance work.

On Windows, install the development/MF4 extras and the optional diagnostic
`playwright` package. Use an installed Edge browser; do not download Chromium.
From the repository root, run:

```powershell
python benchmarks/review_large_report.py
```

The script creates its deterministic MF4 fixture under ignored `dist/report-review`
if absent, runs the bounded browser diagnostic, and records raw measurements.
It checks result equality when `result-before.json` exists; without that baseline,
the equality field is null rather than fabricated. The helper needs Windows
Edge and is not a cross-platform product dependency.

Next bounded review should measure the remaining SVG and data-quality pressure
with concrete review tasks. This patch establishes specific navigation behavior;
it does not close human workflow acceptance or 0.10 release readiness.
