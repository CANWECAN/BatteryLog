## Reproduced defect and correction

Custom measurement loaders could supply complex or temporal columns that
pandas converted to numbers before required-value validation. Complex values
lost their imaginary parts; datetime/timedelta values became nanosecond
integers. Eight temperature probes returned PASS with a maximum of 30 despite
unsupported source values. This contradicts the scalar-real measurement
contract and can produce misleading engineering evidence.

Both whole-frame and streaming analysis now use one small shared conversion
helper. Native complex and temporal columns remain invalid; mixed object and
categorical complex entries are masked locally before conversion. The original
frame stays unchanged, so existing data-quality classification distinguishes
non-numeric values from genuinely missing entries. Strict mode raises; exclude
mode records the defect and excludes the entire row.

The change adds no unit conversion, threshold or schema. Existing real numeric
inputs, numeric strings, nullable floats and Decimal objects retain their
binary64 behavior. Complex-typed columns with zero imaginary parts are also
unsupported: the adapter must explicitly supply real measurements.

The Windows type checker also exposed two existing temporary-file wrapper
typing errors. An explicit BinaryIO cast resolves the annotation without
changing execution. Package-wide mypy now runs in the existing Windows CI job.
