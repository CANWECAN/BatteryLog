## Defect and resulting behavior

The violation table was already paged, but the data-quality table created a live
row for every defect event. An alternating-missing CSV with 200,000 data rows
produced 100,000 separate defects, 700,186 DOM nodes and a 4,321,589 px document.

Both large tables now use the existing offline pager. Each retains its complete
embedded record list and renders 100 rows per page. Data-quality filters select
an exact code, exact signal and overlapping source data row interval. Row numbers
are **one-based**, consistent with the result contract; the CSV header is not a
data row. Violation filters continue using original timestamps.

IDs and summary-link handlers are scoped to their respective table. Selecting,
paging or resetting one table does not alter the other table, charts or global
status. The data-quality rows preserve code, start/end row, affected-value count
and every signal. Canonical result JSON and frozen schemas are unchanged.

The implementation shares one private renderer and one inline script between
the two existing tables. It adds no runtime dependency, processing framework,
desktop GUI or new event grouping policy. SVG geometry remains unchanged.

For more than 100 events, JavaScript is required for browsing beyond the first
page. Without it, the first 100 rows and an explicit incomplete-table notice
remain visible; all records are still embedded. Printing includes the displayed
page only. Small tables remain static and contain all their rows.

## Self-review corrections and limits

- I incorrectly described quality rows as zero-based. A real 100k-analysis last-row
  assertion stopped the measurement. Reading the collector and first/last
  canonical records confirmed the one-based contract. The UI wording, fixtures
  and expectations were corrected; a direct CSV-analysis regression was added.
  The failed measurement contributes no final performance sample.
- The first old-source pytest attempt selected the new tree via pytest's inferred
  root. An explicit config/root path fixed this; the initial apparent pass was
  discarded. An assumed test filename did not exist; that command ran no tests.
- A bulk CSS edit initially missed the quality-table print rule. Static CSS
  review exposed the gap; actual print checks then verified the corrected rule.
- The first CORA diagnostic used an internal result-limit field as a YAML key.
  The parser rejected it. The corrected config uses
  `limits.pack_voltage.cell_sum_max_delta_v`. Import-path assertions and an
  external working directory prevent package/source confusion.
- Updating fixture row numbering initially left a stale expected end row and
  one stale filter bound. Failing checks were corrected before the final run.
- Static review found that the earlier Edge sampler enumerated process names
  outside its disappearance exception handler. It now catches that process-race
  window too. No historical sampler crash is claimed to have been reproduced.
- The existing venv lacks setuptools for a no-isolation build. The standard
  isolated build succeeds. This environment failure is not a package regression.

Remaining SVG pressure is measured separately: the previous 100k report contains
100,000 instant lines, 100,000 peak circles and 100,000 peak titles — 300,000
evidence nodes before other markup. Its hash and source identity are preserved.
Merging SVG shapes can change overlap opacity and event tooltips; no such visual
evidence transformation was made in this block.

Serialized records, SVG overlays and browser memory still grow with event
count. No fixed-memory guarantee, human acceptance sign-off or 0.10 release
readiness follows from these observations. The next useful work is a geometry
proposal that preserves overlap and peak evidence, followed by representative
large-report review. Existing release gates remain open.
