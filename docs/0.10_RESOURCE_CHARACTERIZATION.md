# 0.10 development resource characterization

Measured 2026-09-30 on the local combined review tree containing draft PRs #93–#96 and the benchmark changes. This is not a released version or a release acceptance result. Exact revision: `7d588956c77b7f543bff0ae1404b218af8833009`; tree: `d84b34d4c05d09638f155f29fdd2929d79e4f891`. Raw measurements, including all repeats and source identifiers: [JSON](benchmarks/0.10-resource-measurements.json).

## Method

CPython 3.12.14, Linux x86_64, asammdf 8.8.27, psutil 7.2.2. Each workload ran in a fresh child; fixture generation was excluded. The shared container had an 8 GiB memory limit; these timings are observations from that environment, not dedicated-host capacity guarantees. Each matrix used two repeats, 96 cells, 12 temperatures, aligned 10 Hz timestamps and uncompressed MDF 4.10. Two groups means cells and temperatures in separate groups with the same master; it does not test asynchronous vendor clocks.

`steady` stays within limits. `event-pressure` alternates cell 1 between 4.5 V and 3.7 V, producing one overvoltage and one imbalance event on every other row. Independent source counts were checked: all rows analyzed, none excluded, 50,000/100,000 total events at the respective sizes. Both the analysis API and complete CLI HTML report path were measured.

Reproduce each layout/scenario combination with:

```sh
python benchmarks/benchmark_mf4_analysis.py --rows 50000 100000 --repeats 2 --layout single-group --scenario event-pressure --json-out measurement.json
```

Use `multi-group` for the second layout and `steady` for the other scenario. Prefer an editable installation of the intended checkout. File sizes were approximately 41.6/83.2 MiB for one group and 42.0/84.0 MiB for two groups.

## Observations

Values below are medians of two runs; times are seconds and native peak RSS is MiB. Raw sampled RSS and individual repeats are retained in the JSON. No CI timing or RSS limit is introduced.

| Layout | Scenario | Rows | Events | Analysis s | Analysis peak MiB | Report s | Report peak MiB |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: |
| multi-group | event-pressure | 50,000 | 50,000 | 1.726 | 438.2 | 3.196 | 397.1 |
| multi-group | event-pressure | 100,000 | 100,000 | 3.425 | 712.5 | 6.194 | 629.7 |
| multi-group | steady | 50,000 | 0 | 0.871 | 394.3 | 1.077 | 353.4 |
| multi-group | steady | 100,000 | 0 | 1.433 | 652.5 | 1.844 | 570.6 |
| single-group | event-pressure | 50,000 | 50,000 | 1.661 | 349.9 | 3.224 | 309.5 |
| single-group | event-pressure | 100,000 | 100,000 | 2.897 | 577.8 | 5.430 | 547.7 |
| single-group | steady | 50,000 | 0 | 0.630 | 310.4 | 0.765 | 270.0 |
| single-group | steady | 100,000 | 0 | 0.857 | 515.2 | 1.224 | 434.9 |

At 100,000 rows, the event-heavy HTML was approximately 55.5 MiB versus about 0.1 MiB for the steady case. The full report path took about 3.4–4.4 times as long under event pressure. Separate-group steady analysis reached 652.5 MiB versus 515.2 MiB for one group. These comparisons identify inputs that deserve attention; they do not isolate a particular allocation or justify a new processing architecture.

The 64 MiB DataFrame target is not a total memory bound. The result retains individual violation events, and the HTML includes their evidence. Source size, group layout and event count affect resource use. No event truncation, result-schema change or runtime optimization was made in this measurement patch.

## Measurement correction and limits

Linux `resource.getrusage(...).ru_maxrss` can retain the fixture parent's pre-exec high-water mark. A controlled 128 MiB parent allocation reproduced this contamination; an exec-child regression checks that native worker measurement excludes it. Linux now reads the current address-space `VmHWM` from `/proc`, and resolves `/proc/self` to select the correct psutil process when the mounted PID namespace differs from `os.getpid()`. Windows still uses `peak_wset`. Other POSIX fallback measurements have not been validated here.

The baseline is taken before BatteryLog/asammdf workload imports, so import costs are included. Sampling every 10 ms can miss short peaks. Native and sampled RSS have different accounting and are not assumed to be ordered. Two repetitions provide limited evidence; there are no error bars, universal thresholds or direct comparisons with the older Windows measurements. Compressed files, asynchronous masters, invalidation-heavy channels, wider packs and larger event sets remain uncharacterized.

Next bounded investigation: profile the existing event-pressure report path before deciding whether its event serialization cost warrants a small change. Preserve complete evidence and the frozen result-v8 contract.
