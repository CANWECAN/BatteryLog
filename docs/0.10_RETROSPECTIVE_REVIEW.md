## Confirmed keyboard defect

Previous browser checks exercised clicking, paging, scrolling and filtering.
They did not establish that a keyboard-activated page boundary retains usable
focus. In headless Edge, Enter on Last page caused the focused button to become
disabled. The active element either fell to the document body or remained on
the disabled button. First page and Previous page at the first boundary exposed
the same unusable-focus state. Both tables share the affected script.

The new browser assertion fails on the fixed input before the correction.
The raw initial probe is [retained here](benchmarks/0.10-keyboard-before.json).

The shared click handler now remembers whether its button held focus before
rendering. If rendering disables that focused button, it focuses the existing
table region with `preventScroll`. Intermediate-page focus stays on the button.
This is three added runtime lines, with no new runtime dependency or navigation
framework. The existing table regions already have labels and `tabindex="0"`.

redownloading data or regenerating a different analysis workload:

- HTML SHA-256: `2ba829a66aaef6a3f86a57a07d1e639dc1d4a3e973158e27c53cfb4b68931d59`.
- HTML size: 56,960,527 bytes; 100,000 embedded events.
- Windows 11, Ryzen 5 7500F class, 16 GB RAM, installed Edge 154.0.4258.48.
- Three alternating baseline/candidate pairs, fresh headless profiles,
  1440 x 1000, non-file requests blocked, no concurrent builds or analysis.

The candidate adds `content-visibility: auto` and a remembered intrinsic-size
fallback to plot cards, with an explicit visible print override. It changes
CSS only; serialized SVG and event geometry remain in the file. The
[W3C containment specification](https://www.w3.org/TR/css-contain-2/#using-cv-auto)
describes offscreen rendering suppression, as well as sizing, scrolling and
accessibility considerations. This is a browser rendering experiment, not event
decimation or evidence compression.

| Median of three observations | Baseline | Candidate |
| --- | ---: | ---: |
| Load event | 3.392 s | 2.909 s |
| Owned Edge working-set sum peak | 1,776,459,776 bytes | 1,705,996,288 bytes |
| Last-page navigation after visiting charts | 0.222 s | 0.233 s |
| Sum of three chart scroll-and-capture tasks | 3.519 s | 3.299 s |
| DOM nodes | 301,629 | 301,629 |
| Initial / post-visit document height | 5,270 / 5,270 px | 5,270 / 5,270 px |

All six runs retain all events, late-row evidence and overall FAIL; they finish
without the resource guard firing or page errors. All three plot cards remain
400.859375 px tall in this viewport; the print override is computed as visible.
The memory number includes shared pages in summed owned-process working sets,
sampled every 200 ms. It is not unique physical memory, a hard bound or a
measurement of just the initial viewport. All charts are visited during each run.

The approximately 14% load reduction and 4% sampled working-set reduction do not
remove event-proportional parsing, SVG DOM or file growth. Last-page median does
not improve. Screenshot hashes are stable within each variant but differ between
variants. A subsequent visual spot check of the first chart shows the same
envelope, limits and dense markers; no pixel-difference analysis was completed.
That is neither proof of identical pixels nor evidence of altered measurements.

The candidate remains withheld. This single synthetic workload and one browser
do not justify closing the report memory or human acceptance gates. Dense event
overlays also make individual events visually indistinguishable in the pressure
chart; the complete paged table preserves individual evidence but does not solve
that chart-reading problem.

[raw observations](benchmarks/0.10-svg-containment-experiment.json) preserve the
